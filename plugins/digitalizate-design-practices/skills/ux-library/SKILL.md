# UX library

A compiled copy of the Notion database "Design - Best Practices Library". Notion is the source of truth; these files are regenerated by `/ux-sync`. Do not edit `index/` or `references/` by hand.

## What is in here

- `index/_overview.md` — build date, counts, every category and goal with its file path, tag counts. Read this first if you do not know the library.
- `index/by-category/<category>.md` — one line per practice: `ID · title [subcategory] · ★score · tags · use: <when to apply>`.
- `index/by-goal/<goal>.md` — the same lines grouped by the "Helps With" goal, with the category slug at the end so you can jump to the reference.
- `references/<category>.md`, or for large categories `references/<category>/<subcategory>.md` or `references/<category>/part-N.md` (the category index says which file holds each entry) — the full entry: why, implementation steps (**Do.**), metrics, sources, wireframe link, Notion link, and when available `Verify:`, `Verifiable by:` and `Anti-pattern:`.

IDs look like `UX-118`. They are canonical and stable across builds (the build assigns them from `data/id_map.json`), so citing them is safe. Agent-architecture patterns live in a separate skill (`agentic-patterns`, IDs `AGP-xxx`); do not use them for interface work unless the screen is itself an AI/agent feature.

## Score policy

5 = must-have, 4 = very important, 3 = situational, 2 = niche, 1 = theoretical.

- Always consider score 5.
- Consider score 4 by default; drop one only with a stated reason.
- Consider score 3 only when its `use:` context actually matches the screen.
- Scores 1 and 2 only when the user asks for depth or the topic is exactly that.

## How to find the right practices without reading everything

The library is too big to load whole (~200k tokens). Work in three steps.

1. Classify the work. Name the screen type(s) and the one or two goals at stake, then pick categories from the map below. A screen usually maps to two to four categories plus the baseline set.
2. Read only those index files (each is 1-4k tokens). Shortlist the IDs whose score and `use:` context fit.
3. Open the full entries for the shortlist. For a few IDs, `grep -rn "^## UX-118" skills/ux-library/references/` and read the block up to the next `## `. Read a whole reference file only when you are designing deep inside that category.

Never cite an ID you have not opened in `references/`. The index line is for shortlisting, the reference is what you act on.

### Goal → index

When the user states an outcome ("reduce drop-off", "make this less cluttered", "people don't trust the checkout"), start from `index/by-goal/`. The goals are the twenty "Helps With" values from Notion, for example reduce-cognitive-load, drive-conversion-and-decision-making, build-trust-and-reduce-user-anxiety, design-effective-feedback-and-error-states, improve-perceived-performance-and-loading. The overview lists them all with counts.

### Tag search

For a narrow topic, grep the index: `grep -rh "tags: .*keyboard" skills/ux-library/index/by-category/` or `grep -rhi "autosave" skills/ux-library/index/`.

## Using psychology and bias entries responsibly

Entries in Behavioral Psychology, Human Biases in Interfaces, Cognitive Psychology and Gamification describe how people decide. Use them to help the user understand, decide and finish what they came to do. Do not use them to make someone act against their interest: no manufactured urgency, hidden costs, confirmshaming, forced continuity, or defaults that only serve the business. When a request would cross that line, say so, cite the bias, and offer the honest version of the pattern. `ux-review` treats these as dark-pattern findings.

## Citing

Cite as `UX-118 Inline validation on blur` (ID plus title) the first time, ID alone afterwards. When the entry has a `Verify:` line, state whether the screen passes it. When it does not, judge against the **Do.** steps and say which step is unmet.

## Freshness

`index/_overview.md` carries the build date. If it is older than a month, or the user mentions new entries in Notion, suggest `/ux-sync` before relying on counts.
