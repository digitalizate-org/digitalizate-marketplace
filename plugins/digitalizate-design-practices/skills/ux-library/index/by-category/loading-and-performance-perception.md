# Loading & Performance Perception (8)

Reference: references/loading-and-performance-perception.md

- UX-268 · Skeleton Screens for Full-Page Loads (2–10 Seconds) [Loading Patterns] · ★5 · tags: performance, forms · use: Use for page-level loads, card grids, data tables, dashboard widgets, and any container-based layout where content structure is known before data arrives.
- UX-269 · Match Loading Indicator to Operation Type and Duration [Loading indicator selection] · ★5 · tags: performance · use: Apply any time a user must wait for a system operation. Mismatching indicator type to operation context causes confusion about what the system is doing.
- UX-270 · Doherty Threshold — Target Sub-400ms Response for Interactive Operations [Performance and perceived responsiveness] · ★5 · tags: performance, forms, tables · use: Apply to all interactive operations in data-heavy applications — search queries, filter application, record saves, chart renders, table sorts, API…
- UX-271 · Perceived Progress Reduces Wait Frustration [Loading State Design] · ★5 · tags: ai-patterns, performance, forms · use: Use when designing loading states for data-heavy queries, long-running processes, and any operation where users must wait more than 2 seconds.
- UX-272 · Performance Budgeting for Data-Heavy Interfaces [Performance Standards] · ★5 · tags: enterprise, performance, forms · use: During design (IA choices affect performance), development (rendering strategy), and QA (performance regression testing).
- UX-273 · Progress Bars for Deterministic Operations [Progress Communication] · ★4 · tags: workflow, performance · use: Use for file uploads, batch data imports/exports, any multi-phase operation where server-side progress can be communicated in real time.
- UX-274 · Spinners for Short, Simple Loading States [Loading Patterns] · ★4 · tags: performance · use: Use for button loading states after submission, small component updates, and non-structural asynchronous operations under 3 seconds.
- UX-275 · Time Perception — Accurate Estimates Reduce Frustration [Wait Time Communication] · ★4 · tags: ai-patterns · use: Use when designing progress feedback for long-running operations, and when setting user expectations for report generation, data export, or batch processing.
