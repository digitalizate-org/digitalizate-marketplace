## Why
Empty states appear most often when users first interact with a feature — the moment learning is most relevant. A brief explanation of what the panel displays and how to populate it converts a void into a learning opportunity. Including a direct CTA button launching the workflow to populate the state removes the barrier of users having to figure out where to go next. This "pull revelation" pattern is more effective than tutorial flows because help appears precisely when the user is in the relevant context.

## How to implement
- Include a brief description of what content belongs here and why it's valuable.
- Provide an example or illustration showing the populated state.
- Include a primary CTA button that launches the workflow to populate the state ("Create Your First Alert").
- Include a secondary "Learn More" link for users wanting context before acting.
- Where appropriate, offer multiple pathways (import data / start from scratch / view demo data).
- Notably: Atlassian, PatternFly, and Orbit all provide detailed empty state guidelines following this structure.

## Metrics
Applying this pattern can positively influence the following UX metrics:
- **Effectiveness**: Task success rate, Error rate
- **Satisfaction & Perception**: CSAT, Ease-of-use score
- **Engagement & Usage**: Abandonment rate, Bounce rate
**How to measure**: Monitor abandonment rate on pages that previously showed blank or confusing empty states using analytics; run usability tests to measure whether users understand system status and can self-recover without errors.
