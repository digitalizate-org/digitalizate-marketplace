## Why
The best designs don't need explanation, but complex enterprise tools unavoidably require some. Help documentation must be easy to search, focused on the user's task, concise, and list concrete steps — not explanatory prose. The key insight is context: help delivered at the moment of need (in-app, adjacent to the task) is dramatically more effective than documentation in a separate help center. Empty states are high-value delivery points because the user is already in the context that needs explanation.

## How to implement
- Make help documentation fully text-searchable within the app.
- Present documentation in context — tooltips, inline help panels, or contextual sidebars — at the moment of need.
- List concrete numbered steps rather than explanatory prose.
- Use empty states to provide learning cues for unconfigured features.
- Keep help content physically close to the action it explains; a separate help center alone is insufficient for complex workflows.
- Surface a searchable command palette as an in-app discovery mechanism.

## Metrics
Applying this pattern can positively influence the following UX metrics:
- **Effectiveness**: Task success rate, Error rate
- **Efficiency**: Time on task, Support tickets reduction
- **Satisfaction & Perception**: Ease-of-use score, CSAT
**How to measure**: Compare support ticket volume and help-page exit rates before and after contextualizing documentation; run task-based usability tests measuring success rate and time-on-task with in-context help available.
