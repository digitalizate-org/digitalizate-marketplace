## Why
People learn new systems dramatically better from concrete examples than from abstract rules or feature lists. "Here's how to create a report" — with a step-by-step example using realistic data — teaches far more effectively than "Reports can be created by navigating to the Reports section." Empty states in enterprise applications are missed onboarding opportunities — they should show example data that demonstrates the populated experience. Abstract capability descriptions leave users to imagine use cases; concrete examples trigger immediate recognition of value.

## How to implement
- Replace all abstract feature descriptions with concrete examples using realistic (not fictional) data scenarios.
- Design empty states with realistic sample data clearly labeled as examples.
- Provide a "Use sample data" option in complex features that pre-populates a realistic scenario for new users to explore.
- In help documentation, lead with a concrete walkthrough before explaining the general rules.
- Test onboarding comprehension by asking new users to complete a task after reading the documentation — concrete examples should produce significantly better task success rates.

## Metrics
Applying this pattern can positively influence the following UX metrics:
- **Effectiveness**: Task success rate, Error rate
- **Efficiency**: Time on task, Training time
- **Satisfaction & Perception**: Ease-of-use score, Confidence rating
**How to measure**: Use moderated usability testing to compare task success rates and error counts on interfaces with and without concrete examples; track support ticket volume related to the target feature as a longitudinal proxy.
