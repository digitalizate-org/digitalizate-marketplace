## Why
Frame product requirements around what users "hire" a product to do — the job they need accomplished in a specific context — rather than around features or user characteristics. JTBD shifts focus from "who the user is" to "what they're trying to accomplish and why."

## How to implement
- For each significant user request, apply the JTBD format: "When [situation], I want to [motivation], so I can [expected outcome]." Identify functional, social, and emotional jobs separately.
- Design solutions to satisfy the job, not just implement the requested feature.
- Conduct 30–60 minute JTBD interviews focused on context and timeline of decisions, not opinions about specific features.

## Metrics
Applying this pattern can positively influence the following UX metrics:
- **Effectiveness**: Task success rate, Findability score, Direct success rate
- **Efficiency**: Time on task, Completion time
- **Engagement & Usage**: Abandonment rate, Sessions per user
- **Satisfaction & Perception**: Ease-of-use score, CSAT
**How to measure**: Use tree testing and usability task testing across all four information-seeking modes (known-item, exploratory, exhaustive, re-finding) to measure findability scores and direct success rates. Track search and filter usage analytics to confirm that the interface supports diverse seeking behaviors, and monitor abandonment rates in search flows.
