## Why
The Kano model categorizes features into three types: Must-Be (basic expectations that cause dissatisfaction if absent — hygiene factors), Performance (linear relationship between investment and satisfaction — more = better), and Attractive/Excitement (unexpected features that delight when present but aren't missed if absent). Build all Must-Bes first — their absence creates active dissatisfaction. Then maximize Performance features for competitive differentiation. Add Attractive features for delight. Critically, Attractive features become Performance and then Must-Be over time as market expectations rise, requiring continuous reassessment.

## How to implement
- Run a Kano survey using functional and dysfunctional question pairs for each candidate feature ("How would you feel if this feature existed?" + "How would you feel if this feature didn't exist?").
- Categorize features using the Kano scoring matrix.
- Prioritize: Must-Bes (any absent ones block progress) → Performance features (highest ROI investment area) → Attractive features (differentiation).
- Use the model in roadmap discussions to explain why basic reliability must precede new features.

## Metrics
Applying this pattern can positively influence the following UX metrics:
  - **Adoption & Retention**: Feature usage, Returning visitors, Renewed subscriptions
  - **Satisfaction & Perception**: CSAT, NPS, App store rating
  - **Engagement & Usage**: Active users, Sessions per user
  **How to measure**: Track feature adoption rates for Kano-categorized features (basic needs, performance, delighters) post-launch and compare against predicted prioritization impact. Use follow-up satisfaction surveys segmented by which features users interact with to validate Kano model predictions.
