## Why
Create a visual map of the complete user journey by placing major workflow stages across the top axis and individual user stories beneath each stage, ordered by priority. Story maps provide a holistic view of the user experience that feature lists and backlogs cannot, revealing gaps between workflow stages, enabling slice-based release planning, and maintaining the user's perspective throughout planning. The "minimum slice" — one story per stage that creates a complete if minimal end-to-end experience — defines a valuable MVP scope.

## How to implement
- Identify the 5–8 major stages in the user's primary workflow (from initial intent to final outcome).
- List all known user stories beneath each stage.
- Identify the minimum slice: the single most essential story per stage that would create a complete (if minimal) end-to-end experience.
- Use this minimum slice as your MVP definition.
- Draw a horizontal line separating MVP stories from future enhancement stories.
- Use the map in sprint/cycle planning to ensure no stage is left empty in any given release.

## Metrics
Applying this pattern can positively influence the following UX metrics:
  - **Effectiveness**: Task success rate, Completion rate
  - **Efficiency**: Time on task, Support tickets reduction
  - **Adoption & Retention**: Feature usage, Returning visitors
  **How to measure**: Map story map activities to product analytics events and track completion rates per story-mapped user journey phase. Use story maps to identify gaps in instrumentation, then measure whether workflow coverage improvements correlate with reduced support tickets and higher end-to-end task success.
