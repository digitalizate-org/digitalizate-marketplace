## Why
Users identify objects, find interface elements, and navigate applications primarily by recognizing visual patterns, not by reading labels. Consistent visual patterns for consistent functions (all primary action buttons look the same, all navigation items use the same visual style) reduce the cognitive effort of navigation to zero for learned patterns. Breaking established patterns — even for good visual design reasons — creates cognitive friction users experience as confusion and distrust. Pattern consistency is the foundation of all efficient enterprise application usage.

## How to implement
- Establish a component library with visually distinct and consistent patterns for each interaction type.
- Never reuse a visual pattern for a functionally different element — a link that looks like a button or a button that looks like a label creates systematic confusion.
- Conduct a pattern consistency audit: can users identify the function of each element type at a glance by appearance alone? When introducing new patterns, provide transition periods and clear visual distinction from existing patterns.

## Metrics
Applying this pattern can positively influence the following UX metrics:
- **Efficiency**: Time on task, Training time
- **Effectiveness**: Task success rate, Error rate
- **Satisfaction & Perception**: Ease-of-use score, CSAT
**How to measure**: Measure time on task and error rate for new users performing standard interactions on a product with high pattern consistency versus one with inconsistent UI patterns. Track training time or onboarding completion time as an indicator of how quickly users build accurate mental models.
