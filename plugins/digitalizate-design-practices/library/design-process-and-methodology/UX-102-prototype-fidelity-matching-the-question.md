## Why
Match prototype fidelity to the specific question being tested. Early prototypes should be rough, rapid, and "right enough" — lower fidelity means less time per iteration and more learning per hour. As questions get answered and designs mature, increase fidelity incrementally. Using high-fidelity prototypes to test conceptual questions wastes resources and biases users toward visual details (color choices, typography) rather than structural feedback (does this workflow make sense?). The goal is maximum learning per unit of prototype investment.

## How to implement
- Before building any prototype, explicitly state: "The question this prototype answers is [X]." For conceptual questions (does this workflow make sense?), use paper sketches or low-fi wireframes.
- For flow questions (can users complete this task?), use interactive wireframes.
- For trust/quality questions (does this feel professional?), use high-fidelity mocks.
- Never add fidelity beyond what the question demands.
- Test each prototype with users before advancing to higher fidelity.

## Metrics
Applying this pattern can positively influence the following UX metrics:
- **Effectiveness**: Task success rate, Completion rate
- **Efficiency**: Time saved per task, Error rate reduction
- **Satisfaction**: Perceived design quality, Learnability
**How to measure**: Track prototype iteration cycles and time-per-iteration; measure user feedback quality (structural vs. visual comments ratio); count rework hours attributable to late-stage redesigns caught by appropriate fidelity testing.
