## Why
Wireframes that include layout details set visual expectations that constrain designers and distract stakeholders from the real questions: what content belongs here, in what priority order, and with what functionality. Page description diagrams communicate content and priority without prescribing layout, enabling the right design conversation at the right stage. This prevents premature convergence on a layout before content decisions are fully resolved.

## How to implement
- Use diagrammatic representations showing content priority and relationships without implying specific visual arrangements.
- Reserve layout decisions for the visual design phase.
- Annotate functional requirements and behaviors on wireframes separately from visual design specifications.
- Use wireframes as "starting points for grounding design studies" rather than final specifications.
- Separate content priority reviews from layout reviews in stakeholder sessions to prevent premature visual fixation.

## Metrics
Applying this pattern can positively influence the following UX metrics:
- **Effectiveness**: Task success rate, Findability score
- **Efficiency**: Time on task, Completion time
- **Satisfaction & Perception**: Ease-of-use score, CSAT
**How to measure**: Document content priority decisions before visual layout work begins, then run a first-click test after design to verify alignment. Compare task success rates on pages designed with explicit content hierarchy versus pages where layout drove prioritization decisions.
