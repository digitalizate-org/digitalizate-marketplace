## Why
UX work that happens only within development sprints is constantly reactive — design decisions are made under time pressure and validated only after implementation, when changes are expensive. A "Sprint 0" or "Iteration 0" where UX defines the wireframe stack before development planning reduces costly mid-sprint redesigns. UX architecture is too expensive to fully redesign each sprint — stabilizing core patterns early is essential for maintaining velocity.

## How to implement
- Maintain a UX sprint ahead of the development sprint to provide validated wireframes for sprint planning.
- Create a complete wireframe stack as a key deliverable before release planning.
- Design UX to gracefully degrade if features are removed from scope — flexibility prevents full redesigns from scope changes.
- Treat core UX architecture as stable once validated — don't redesign foundational patterns each sprint without strong evidence.

## Metrics
Applying this pattern can positively influence the following UX metrics:
- **Effectiveness**: Task success rate, Completion rate
- **Efficiency**: Time saved per task, Support tickets reduction
- **Satisfaction**: Developer/designer velocity, Team satisfaction
**How to measure**: Track mid-sprint redesign frequency and sprint velocity before and after implementing design sprints; measure rework rate (hours spent redoing design decisions) as a key efficiency indicator.
