## Why
The Double Diamond structures design work into two phases, each containing a divergent phase followed by a convergent phase. Diamond 1 (Problem Space): Discover (explore widely to understand the problem) → Define (converge on the specific problem to solve). Diamond 2 (Solution Space): Develop (generate many possible solutions) → Deliver (implement the best solution). This structure prevents the most common design failure mode: jumping to solutions before the problem is fully understood, resulting in well-executed solutions to the wrong problem.

## How to implement
- Allocate explicit time for each phase and resist the temptation to compress Discover/Define.
- Use user research (interviews, contextual observation) in the Discover phase.
- Define a clear, written problem statement agreed by all stakeholders before entering the Develop phase.
- Use prototyping and testing in the Develop phase before committing to Deliver.
- If research in Discover contradicts the assumed problem, restart the Define phase — this is correct behavior, not wasted time.

## Metrics
Applying this pattern can positively influence the following UX metrics:
- **Effectiveness**: Task success rate, Completion rate
- **Satisfaction & Perception**: NPS, CSAT
- **Adoption & Retention**: Account creation rate, Returning visitors
**How to measure**: Compare product outcomes (task success rate, NPS) for initiatives that went through a full double-diamond process versus expedited projects. Use retrospective surveys to assess whether thorough discovery phases reduce post-launch redesign cycles and improve satisfaction scores.
