## Why
Users scan navigation items rather than reading them linearly. Labels that begin with the most descriptive word allow rapid scanning without reading further. Generic or vague labels ("Manage," "Work With," "Tools") force users to read more context to extract meaning and increase cognitive load. Navigation labels are the primary affordance for system navigation — poorly written labels directly translate to users getting lost and failing tasks.

## How to implement
- Start navigation labels with the key noun or action ("Invoices" not "Manage Billing Items").
- Use plain, user-familiar language — validate labels through card sorting with actual end users.
- Keep labels to 1–3 words maximum for primary navigation.
- Avoid internal jargon, system-name abbreviations, and acronyms users won't recognize.
- Test label comprehension by asking users to predict what's behind each label before clicking.

## Metrics
Applying this pattern can positively influence the following UX metrics:
- **Effectiveness**: Findability score, Task success rate
- **Efficiency**: Time on task, Tree-test score
- **Engagement & Usage**: Bounce rate, Pages per session
**How to measure**: Conduct tree testing comparing current versus front-loaded label variants to measure direct success rates; monitor bounce rate and time-on-navigation via analytics before and after label updates.
